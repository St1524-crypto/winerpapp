# 修正會員改密碼後無法登入

## 目標
- 將會員密碼重設集中到單一安全流程，避免輸入內容與實際儲存不一致。
- 當密碼正確但官網 ID 選錯時，顯示可行動的公司入口提示，而不是一律顯示帳密錯誤。
- 重設完成後由伺服器立即驗證新密碼，並回報會員所屬官網 ID。

## 實作
1. 強化後台密碼工具：新增再次輸入確認、拒絕前後空白、重設後顯示「登入驗證成功」與正確官網 ID。
2. 停止在會員基本資料編輯表單混合修改密碼，統一使用密碼工具，避免兩條流程行為不同。
3. 強化登入識別：公司範圍查無帳號時，以有效帳密安全確認是否為公司入口不符；僅在帳密已驗證後回傳正確官網 ID 提示，不洩漏帳號是否存在。
4. 同步管理員與會員登入頁的錯誤訊息，讓使用者能直接改用正確入口。

## 驗證
- 執行 TypeScript 檢查與相關測試。
- 驗證密碼不一致、前後空白、正確重設、錯誤公司入口及錯誤密碼等情境。
- 不修改資料庫結構、不變更既有會員資料、不發布。

## 技術細節
- 保持權限檢查與服務端密碼更新；驗證用獨立、不持久化的公開認證客戶端，避免污染管理端身分。
- 公司提示只在密碼驗證成功後提供，維持防帳號列舉設計。
